Selected work

Calimero engineering lead

A hackathon prototype of mine became the company's platform. Calimero runs sandboxed application logic on users' own nodes, with encrypted shared state kept in sync over a P2P network. I designed both generations of the protocol, first a transactional prototype and then an eventually consistent CRDT-based redesign, and wrote the specification the company adopted. I built the networking, state storage and recursive sync layers, plus the Wasmer-based runtime foundation and guest SDK, so app developers could use familiar data structures while replication happened underneath. Then I led the whole engineering team, most of them new to Rust, and reviewed most of what shipped.

NEAR core engineer

I was brought in for engineering rigour. Account IDs were plain strings, validated only at the points someone remembered to check. I led the move to a typed AccountId that is parsed once and valid from then on (it later became its own crate), and the stricter type surfaced invalid values already sitting in live network state. An internal test client I built grew into NEAR's standard Rust JSON-RPC client. I built Themis, the compliance checks every crate in the repository has to pass. Then I maintained both sides of the contract runtime boundary, the node's VM interface and the guest side in the Rust SDK, where I helped introduce contract ABIs and wrote the NearSchema derive. I also hunted down and documented exploits in the BOS platform. I follow a problem to its logical conclusion.

theia what I'm building now

SSH into a machine, send it files, forward a port or fetch through it, knowing only its public key. No account and no addresses to manage. The host decides who gets which service and until when, and taking access back ends an open session in under a second. Access is a capability rooted in the same key and checked offline. The transport underneath is swappable: iroh today, next to a UDP transport I wrote from scratch, with one conformance suite holding both to the same identity contract. I've designed and am now implementing QUIC over mixed IP and non-IP links, so nearby machines can keep working together over whatever link they share.

It's a stack of small crates: bifrost (reach), nauthy (capabilities), tightbeam (tunnels), services (ssh, transfer, fetch, measure) and swoosh, the one CLI on top.

Explorations

I explore just past the edge of what I know, and I experiment all the time. Some of these shipped. Some only ever existed to answer a question.

  • quirk: a QUIC-shaped transport from scratch over UDP, to learn what a modern transport actually has to do. Not for production, on purpose.
  • Process continuity: what does it take to move a running process to another machine and have it carry on? Memory on demand with userfaultfd is the easy part; open handles, storage and ordering are where it gets interesting. Ongoing.
  • Next up: sandboxing experiments.
  • qat: a throwaway box on a CI runner that you SSH into by public key, gone when its timer runs out.
  • xget: a chunked, parallel, resumable, verified fetch engine over a pluggable byte source.
  • janus: a reverse proxy written in Rust, running as a Cloudflare Worker.
  • zy: a minimal static file server in Rust.
  • cryptographic experiments, and a long tail of smaller ones on GitHub and crates.io.
  • freyr: the one that got away from me. A music downloader with 2.3k stars and 42k+ Docker pulls.

I've been writing Rust since just before 1.0. Before that it was Arch Linux, kernel modules and FUSE filesystems as a teenager, mostly to see how things worked. Along the way: merged contributions to tickrs, Apache Arrow, rustyline and dialoguer.

Approach
